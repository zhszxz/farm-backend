| 项目 | 内容 |

## 1. 项目概述

### 1.1 项目背景

农户（老家务农的父母）长期种植瓜果等农副产品并进行简单加工（如果干、果酱等），目前缺少一个对外展示的窗口，也缺少对每年产销数据的系统化记录与分析。经营数据（某年某品种卖了多少钱、走什么渠道、成本多少）通常停留在纸质账本或零散 Excel 中，难以做跨年度对比和利润核算。

因此需要一个平台，既能展示产品、扩大客源，又能帮助农户用数据管理每年的产销与利润情况。

### 1.2 项目目标

1. **展示**：以图文形式展示农副产品（瓜果及简单加工产品），让外界了解产地、品种、上市季节、种植/加工过程。
2. **引流**：将有意向购买的用户引导到商家已有的**拼多多**店铺完成下单，平台自身**不涉及支付、订单、物流、售后**。
3. **数据化经营**：商家可录入每年各类农产品的**销售、产量、成本**数据，生成图表报表，**核算利润**、辅助决策。
4. **多商户**：平台可容纳多个商家入驻，各自维护店铺、产品与产销数据。

### 1.3 建设范围（一期，本次确认）

- ✅ 产品展示
- ✅ 引流到拼多多（父母已有小店）
- ✅ 三类用户体系（普通用户 / 商家 / 管理员）与多商户入驻
- ✅ 商家产销数据录入（销售 / 产量 / 成本，含 Excel 导入）
- ✅ 利润核算（利润 = 销售额 − 成本）
- ✅ 数据报表（趋势折线、对比柱状、占比饼图、利润、排行、导出）
- ✅ 后台管理
- ❌ **不做商城**：不做在线支付、购物车、订单、库存、物流、售后（远期可选，预留扩展，见 9.2）

### 1.4 已确认的关键决策

| 决策项 | 结论 |
| --- | --- |
| 是否自建商城 | **否**。交易引导到第三方平台完成 |
| 引流目标 | **拼多多**（父母已开通小店） |
| 商户模式 | **多商户**平台（开放入驻 + 管理员审核） |
| 终端形态 | **H5 网页**，移动端优先、响应式（暂不做小程序） |
| 技术栈 | **Vue 3 + Spring Boot + MySQL 8** |
| 报表技术 | **ECharts**（图表）+ **EasyExcel**（导出 Excel） |
| 产品分类 | **两级**：大类（苹果）+ 小类（红富士） |
| 登录方式 | 手机号 + 密码 / 手机号 + 短信验证码（微信登录二期可选） |
| 短信服务 | 阿里云短信 / 腾讯云短信 |
| 用户角色 | 普通用户 / 商家 / 管理员 三类 |
| 产量/成本记录 | **必做**，用于核算利润 |
| 利润核算 | 利润 = 销售额 − 成本；利润率 = 利润 ÷ 销售额 |
| 远期商城 | **预留扩展点**，本期不实现 |

## 3. 功能需求

### 3.1 农产品展示模块

- **分类浏览**：按大类（苹果/梨/桃/果干…）和小类（品种）浏览。
- **搜索与筛选**：按名称、大类/小类、上市季节、产地等搜索筛选。
- **产品详情页**：
  - 图片集（多图）
  - 产品介绍、产地、种植/加工方式、上市季节、规格与计量单位
  - 营养价值、食用/储存建议（可选）
  - 所属商家/农场信息与联系方式
  - **"去购买"按钮**：跳转到商家的拼多多店铺（见 3.5）
- **商家/农场主页**：农场简介、所在地、联系方式、产品列表、拼多多店铺入口。
- **首页推荐位**：轮播图、推荐产品、应季产品（由管理员配置）。
- **收藏/关注**：普通用户收藏产品、关注商家。
- **留言/咨询**：用户可留言咨询（商家后台可见并回复）。

### 3.2 用户中心

- **注册/登录（一期）**：
  1. **手机号 + 密码**：注册时用短信验证码验证手机号
  2. **手机号 + 短信验证码**：免密登录（对中老年与顾客最友好）
  3. **账号 + 密码**：备选（不依赖短信）
- **微信授权登录**：二期可选（需认证服务号/开放平台，约 ¥300/年）。
- 个人资料管理。
- 我的收藏、我关注的产品/商家。
- 商家身份申请（升级为商家，见 4.1）。

### 3.3 商家数据录入模块（核心）

商家工作台包含：

**（1）店铺管理**
- 店铺名称、所在地区（省/市/县/乡镇）、详细地址、联系人、联系电话、简介、资质证明（可选）。
- 拼多多店铺链接配置（见 3.5）。

**（2）产品管理**
- 新增/编辑/上下架产品。
- 产品字段：大类、小类（品种）、计量单位、图片、简介、上市季节、状态（草稿/已上架/已下架）。

**（3）销售记录录入**
> 对应原始需求："某年某品种通过某渠道销售了多少斤多少钱"。

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 年份 | 销售所属年份 | 是 |
| 产品/品种 | 关联到具体产品（小类） | 是 |
| 销售渠道 | 下拉选择（电商/批发/商超/合作社/采摘/零售/单位采购/直播等） | 是 |
| 数量 | 销售数量 | 是 |
| 单位 | 斤/公斤/箱/吨（下拉） | 是 |
| 销售额 | 金额（元） | 是 |
| 单价 | 可自动计算（销售额/数量），也允许手动填 | 否 |
| 销售时间段 | 如"2023年10月"或具体起止日期 | 否 |
| 备注 | 自由填写 | 否 |

- 支持**批量录入**与 **Excel 导入**（重要：农户往往已有纸面/Excel 记录，应支持模板导入）。
- 支持编辑、删除、按年份/产品/渠道筛选查看。
- 录入时的**数据校验**与友好提示（如数量不能为负、单价异常提醒）。

**（4）产量与成本记录（必做，支撑"产量"报表与利润核算）**
- **产量记录**字段：年份、品种、种植面积（亩）、产量、单位、备注。
- **成本记录**：分项维护（化肥、农药、人工、包装、物流、其他等，类型字典可配置），每条含：年份、品种、成本类型、金额、备注。
  - 同时支持**简化模式**：按"年 + 品种"直接记一个总成本，降低录入负担。
- 目的：支撑"跨年产量趋势折线图"，并与销售记录联动核算：
  - **利润 = 销售额 − 成本**
  - **利润率 = 利润 ÷ 销售额**

### 3.4 数据报表模块（核心）

商家可查看**自有数据**报表，管理员可查看**全平台**报表。图表基于产销成本记录动态生成。

| 报表类型 | 图表形式 | 说明 |
| --- | --- | --- |
| 单品跨年趋势 | 折线图（双 Y 轴） | X 轴=年份；可同时展示某产品的**产量、销量、销售额**变化 |
| 某年各产品对比 | 柱状图 | 某年份不同农产品的销售额/销量对比 |
| 渠道占比 | 饼图/环形图 | 某年各销售渠道销售额占比 |
| 品类占比 | 饼图/环形图 | 某年各大类/小类销售额占比 |
| 利润核算 | 柱状图/折线图 + 表格 | 按年/品种/品类核算利润与利润率，含跨年利润趋势 |
| 排行榜 | 横向条形图/表格 | 销售额 Top N、销量 Top N |
| 同比/环比 | 卡片 + 表格 | 今年 vs 去年增长情况 |

- **多维度筛选器**：按年份范围、产品、大类/小类、渠道自由组合筛选。
- **数据导出**：报表数据导出 Excel（EasyExcel），图表导出为图片。
- **权限隔离**：商家只能看到自己店铺的数据，绝不可见他人数据。

### 3.5 引流到拼多多模块

平台**不承接交易**，只把流量导给商家的拼多多店铺：

- **商家配置店铺链接**：商家在后台维护拼多多店铺信息（店铺名称、店铺/商品分享链接）；可配置多个商品链接分别对应不同产品。
- **"去购买"入口**：产品详情页与商家主页展示"去拼多多购买"按钮，点击跳转。
- **二维码分享**：生成产品/店铺的分享二维码，方便父母在微信朋友圈、群里传播。
- **联系方式展示**：电话、微信号（一键复制）等咨询入口。
- **跳转统计（可选）**：记录各产品/店铺的跳转点击次数，商家可查看引流效果，管理员看全平台汇总。

> 合规说明：因交易在拼多多完成，本平台自身**不涉及支付、订单、物流、售后**，也不需要支付商户号、食品经营许可等商城资质（详见第 10 节）。

### 3.6 后台管理模块

- **用户管理**：查看、禁用/启用账号、角色管理。
- **商家入驻审核**：审核商家申请（资质、真实性），通过后商家方可发布产品。
- **内容审核**：审核/下架违规产品。
- **字典管理**：销售渠道、成本类型、计量单位、大类/小类等枚举项维护。
- **推荐位管理**：首页轮播、推荐产品的配置。
- **平台整体统计**：全平台产品数、商家数、汇总产销数据、跳转统计。
- **系统配置与操作日志**：基础配置、关键操作留痕。

## 4. 关键业务流程

### 4.1 商家入驻流程

```
普通用户注册 → 提交商家申请（店铺信息/资质）→ 管理员审核
  ├─ 通过 → 开通商家工作台（可发布产品、配置拼多多链接、录入数据）
  └─ 不通过 → 退回并告知原因，可修改后重新提交
```

### 4.2 产销数据录入流程

```
商家进入工作台 → 选择"销售记录 / 产量记录 / 成本记录"
  → 手动逐条录入 或 下载模板/导入 Excel
  → 系统校验数据 → 保存 → 数据即时进入报表与利润核算
```

### 4.3 报表查看流程

```
商家进入"数据报表" → 选择报表类型（趋势/对比/占比/利润/排行）
  → 选择筛选条件（年份、产品、渠道）→ 图表动态渲染 → 可选导出
```

### 4.4 引流购买流程

```
用户浏览产品/店铺 → 点击"去拼多多购买"按钮 或 扫码
  → 跳转到商家拼多多店铺 → 在拼多多完成下单
```

## 5. 数据模型（核心实体）

| 实体 | 关键字段 |
| --- | --- |
| 用户 User | 用户ID、账号、手机号、密码(加密)、角色、状态、注册时间 |
| 店铺 Shop | 店铺ID、所属用户、名称、地区、地址、联系人、电话、简介、审核状态 |
| 拼多多链接 ShopLink | 链接ID、店铺、产品(可空)、店铺/商品名称、链接地址、状态 |
| 产品分类 Category | 分类ID、名称、父级ID（自关联两级：大类→小类）、排序 |
| 产品 Product | 产品ID、所属店铺、分类(关联**小类**)、单位、图片集、简介、上市季节、状态、**预留:价格/库存/SKU** |
| 销售渠道 Channel | 渠道ID、名称、排序（字典） |
| 成本类型 CostType | 类型ID、名称、排序（字典） |
| 销售记录 SalesRecord | 记录ID、店铺、产品、年份、渠道、数量、单位、销售额、单价、销售时间段、备注、创建时间 |
| 产量记录 ProductionRecord | 记录ID、店铺、产品、年份、种植面积、产量、单位、备注 |
| 成本记录 CostRecord | 记录ID、店铺、产品、年份、成本类型、金额、备注 |
| 跳转统计 ClickLog | 记录ID、店铺/产品、点击时间、来源（可选） |
| 收藏/关注 Favorite | 用户、产品/店铺、时间 |
| 留言咨询 Message | 用户、商家、内容、回复、状态、时间 |

> **分类层级**：`Category` 通过 `parent_id` 自关联实现**两级**（大类→小类）；产品关联**小类**，大类由父级推导，报表可按大类或小类聚合。

> **报表与利润**为**统计视图**，不单独存表：利润 = 按「店铺 + 年份 + 品种」汇总销售额 − 汇总成本，按需实时或缓存计算。

> **商城预留**：`Product` 表预留 `price`（价格）、`stock`（库存）、`sku`（规格）等字段（本期置空）；`ShopLink` 未来可平滑替换为"站内下单"入口；订单/支付模块作为远期独立扩展，不重构现有表。

## 6. 非功能需求

### 6.1 易用性（重点：面向中老年农户）

父母辈是核心使用者，易用性是最高优先级：

- **大字体、简洁界面**：图标 + 文字，配色温和，减少信息密度。
- **移动端优先**：H5 网页响应式设计，手机浏览器体验优先。
- **录入尽量"点选"**：渠道、成本类型、单位、大类/小类等一律下拉选择，减少文字输入。
- **图片上传简单**：拍照即传、自动压缩，避免大图上传失败。
- **图表直观**：报表以图形为主、配浅显文字说明（如"今年比去年多赚了 X 元"），避免复杂术语。
- **防误操作**：删除有二次确认、关键操作有提示。
- **弱网友好**：图片懒加载，适配农村较弱的网络环境。

### 6.2 性能

- 常规页面加载 ≤ 3 秒；报表查询 ≤ 5 秒（数据量小时应更快）。
- 图片走对象存储 + CDN 加速。

### 6.3 安全

- 密码加密存储、登录态安全（Token/HTTPS）。
- **权限严格隔离**：商家数据之间、商家与平台数据之间不可越权访问。
- 输入校验与防注入（XSS/SQL 注入）。
- 商家内容与入驻需审核；外部链接需校验（防钓鱼）。
- 短信验证码防刷（频率限制、图形验证码前置）。

### 6.4 兼容性

- 主流手机浏览器（微信内置浏览器、Safari、Chrome）及主流桌面浏览器。
- 响应式布局适配不同屏幕尺寸。

### 6.5 可扩展性（为远期商城预留）

- 产品实体预留价格、库存、SKU 字段。
- 引流链接采用独立 `ShopLink` 表，未来可平滑替换为"站内下单"入口。
- 前后端分层、模块化，若未来决策自建商城，作为新增模块接入，不重构现有功能。

### 6.6 数据可靠性与备份

- 数据库定期自动备份。

## 8. 技术选型（已确认）

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | H5 网页，**Vue 3** + Element Plus（桌面）/ Vant（移动） | 移动端优先、响应式，本期不做小程序 |
| 后端 | **Spring Boot 3**（Java）+ MyBatis-Plus | RESTful API |
| 数据库 | **MySQL 8** | 结构化数据，报表统计 |
| 图表 | **ECharts**（vue-echarts 封装） | 双 Y 轴折线/柱状/饼图全覆盖，免费开源，支持图片导出 |
| Excel 导出 | **EasyExcel**（阿里，后端） | 报表数据导出 Excel |
| 文件存储 | 云对象存储（OSS/COS）+ CDN | 图片托管 |
| 短信 | **阿里云短信 / 腾讯云短信** | 注册登录验证码（约 0.03~0.05 元/条） |
| 部署 | 云服务器（国内）+ 域名备案 | 国内访问需 ICP 备案 |

> **报表技术方案**：前端 ECharts 渲染图表；后端 SpringBoot 用 SQL 聚合（GROUP BY）返回 JSON；Excel 用 EasyExcel 导出。数据量小，不引入 BI/OLAP 引擎。

> **合规说明**：本期不做支付、不做订单，因此**不需要**微信支付/支付宝商户号、EDI 证等商城资质，合规成本大幅降低。域名仍需 ICP 备案。

## 10. 风险与待确认问题

### 已确认决策（本次）

| 决策项 | 结论 |
| --- | --- |
| 是否自建商城 | 否，引流到拼多多（父母已有小店） |
| 商户模式 | 多商户 |
| 终端形态 | H5 网页 |
| 技术栈 | Vue 3 + Spring Boot + MySQL 8 |
| 报表技术 | ECharts + EasyExcel |
| 产品分类 | 两级（大类 + 小类） |
| 登录方式 | 手机号+密码 / 手机号+验证码（微信登录二期） |
| 短信服务 | 阿里云/腾讯云短信 |
| 是否做支付/订单/物流 | 否 |
| 是否记录产量/成本 | 是，必做，用于利润核算 |
| 商城预留扩展 | 是，仅预留字段与设计，不实现 |

### 待确认（建议进入开发前明确）

1. **计量单位**：是否需要统一单位换算（斤/公斤/吨/箱）？（品种粒度已定为"大类+小类"）
2. **成本记录粒度**：成本按"年+品种"记总数即可，还是需要分项（化肥/农药/人工/包装/物流）？（建议支持分项，但录入要简单）
3. **拼多多链接形式**：从拼多多商家后台获取的是店铺链接还是商品链接？是否能稳定跳转（拼多多外链规则需确认）。
4. **微信登录是否一期做**：需认证服务号/开放平台（约 ¥300/年），建议二期再做。
5. **域名与主体**：ICP 备案需要主体（个体户营业执照即可），建议尽早办理。

### 主要风险

| 风险 | 应对 |
| --- | --- |
| 父母使用门槛高 | 大幅简化交互、移动端优先、大字体、点选式录入 |
| 历史数据零散 | 提供 Excel 导入模板，先帮录入近 1–2 年数据 |
| 跳转后用户流失 | 提供二维码分享、联系方式，尽量在平台内完成"种草"，跳转仅作为成交 |
| 拼多多外链失效/规则变化 | 商家可自助维护链接，管理员可审核；关注拼多多外链政策 |
| 利润核算口径不一致 | 明确"利润 = 销售额 − 成本"，成本口径（是否含人工/运费）需与父母对齐 |
| 短信验证码被刷 | 频率限制 + 图形验证码前置 |
| 域名备案需主体资质 | 提前用个体户执照完成备案 |

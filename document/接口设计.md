## 1. 通用规范

### 1.1 基础约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api` |
| 协议 | HTTPS（生产） |
| 认证 | JWT，请求头 `Authorization: Bearer <token>` |
| 内容类型 | `application/json; charset=utf-8` |
| 日期时间 | `yyyy-MM-dd HH:mm:ss`；纯年份用 `year`（如 2024） |

### 1.2 统一响应格式

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- `code = 0` 成功；非 0 失败。
- 分页接口 `data` 结构统一为：

```json
{
  "records": [],
  "total": 100,
  "page": 1,
  "size": 10
}
```

### 1.3 错误码

| code | 含义 | HTTP |
| --- | --- | --- |
| 0 | 成功 | 200 |
| 40001 | 参数校验失败 | 400 |
| 40002 | 短信验证码错误/过期 | 400 |
| 40003 | 账号或密码错误 | 400 |
| 40004 | 手机号已注册 | 400 |
| 40100 | 未登录 / token 失效 | 401 |
| 40300 | 无权限（如普通用户访问商家接口） | 403 |
| 40400 | 数据不存在 | 404 |
| 50000 | 服务器内部错误 | 500 |

### 1.4 权限标识

| 标识 | 含义 |
| --- | --- |
| 公开 | 无需登录 |
| 登录 | 需有效 token |
| 商家 | 需 `role=2` 且店铺审核通过 |
| 管理员 | 需 `role=3` |

### 1.5 枚举字典

| 字段 | 值 |
| --- | --- |
| `role` | 1-普通用户 2-商家 3-管理员 |
| `shop.status` | 0-待审核 1-通过 2-驳回 |
| `product.status` | 0-草稿 1-已上架 2-已下架 |
| `targetType` | 1-产品 2-店铺 |
| `message.status` | 0-待回复 1-已回复 |
| `unit` | jin-斤 kg-公斤 box-箱 ton-吨 |

## 3. 重点接口示例

### 3.1 发送验证码

`POST /api/auth/sms-code`

```json
{ "phone": "13800000000" }
```

响应：`{ "code": 0, "message": "ok", "data": null }`

> 验证码存 Redis，5 分钟有效；60 秒内同号限发一次（防刷）。

### 3.2 密码登录

`POST /api/auth/login/password`

```json
{ "account": "13800000000", "password": "abc123" }
```

响应：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "token": "eyJhbGciOi...",
    "user": { "id": 1, "nickname": "老王", "phone": "13800000000", "role": 2 }
  }
}
```

```json
    "unit": "jin",
    "images": ["https://.../a.jpg", "https://.../b.jpg"],
    "description": "...",
    "origin": "老家县",

    "shop": {
      "id": 5, "shopName": "老王家庭农场", "wechat": "laowang",
      "linkUrl": "https://mobile.yangkeduo.com/..."
    }
  }

```

### 3.4 新增销售记录

`POST /api/merchant/sales`

```json
{
  "categoryId": 2,
  "year": 2024,
  "channelId": 1,
  "quantity": 5000,
  "unit": "jin",
  "amount": 15000,
  "unitPrice": 3.00,
  "salePeriod": "2024年10月",
  "remark": ""
}
```

响应：`{ "code": 0, "message": "ok", "data": { "id": 1001 } }`

> 服务端校验：数量/金额 > 0；`unitPrice` 未填时按 `amount/quantity` 计算；`shop_id` 从 token 取，不接受前端传入（防越权）。

## 4. 设计要点与约定

1. **越权防护**：所有商家接口的 `shop_id` 一律从 JWT 解析，**不信任前端传入的 shopId**；报表接口对商家强制 `shop_id=自己`。
2. **验证码防刷**：Redis 限频（同号 60s 一次）+ 图形验证码前置（可选）。
3. **Excel 导入**：`sales/import` 用 `multipart/form-data` 上传 `.xlsx`，后端用 EasyExcel 解析、逐行校验，返回成功/失败条数。
4. **报表缓存**：报表结果可在服务层加 Redis 缓存（如当日数据变动后失效），数据量小时可不缓存。
5. **图片上传**：`POST /api/upload`（登录/商家），上传到 OSS 返回 URL（可并入产品接口或单独提供）。
6. **统一异常**：全局异常处理器返回统一 `{code, message}`。

## 1. 设计约定

| 项 | 约定 |
| --- | --- |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 通用字段 | 每表含 `create_time`、`update_time`、`deleted`（逻辑删除 0/1，MyBatis-Plus 风格） |
| 金额 | `DECIMAL(14,2)`，单位元 |
| 数量 | `DECIMAL(12,2)`（支持小数，如 350.5 斤） |
| 年份 | `SMALLINT` |
| 状态枚举 | `TINYINT` + 注释说明 |
| 字符集 | `utf8mb4`（支持中文与 emoji） |
| 命名 | 表名/字段小写下划线；字典表以 `sys_` 前缀，业务表无前缀 |

> ⚠️ **逻辑删除与唯一键**：MySQL **不直接支持"部分唯一索引"**（`CREATE UNIQUE INDEX ... WHERE deleted=0` 是 PostgreSQL/SQL Server 的 partial/filtered index，MySQL 无此语法）。`deleted` 逻辑删除会让软删记录仍占用唯一键。**推荐用 MySQL 8 函数索引 + NULL 技巧**实现等价效果（InnoDB 唯一索引允许多个 NULL，NULL 不参与唯一性比较）：
> ```sql
> -- 已删除行映射为 NULL，唯一性只约束未删除行
> CREATE UNIQUE INDEX uk_phone_active
>   ON sys_user ((CASE WHEN deleted = 0 THEN phone ELSE NULL END));
> ```
> 等价方案（MySQL 5.7+，生成列 + 唯一索引）：
> ```sql
> ALTER TABLE sys_user
>   ADD COLUMN phone_active VARCHAR(20)
>     GENERATED ALWAYS AS (CASE WHEN deleted = 0 THEN phone ELSE NULL END) STORED,
>   ADD UNIQUE KEY uk_phone_active (phone_active);
> ```
> 因此：
> - `sys_user`（账号/手机号唯一）：用上述**函数索引**（DDL 已采用）。
> - `favorite`（收藏）：收藏/取消用**物理删除/插入**（toggle），不用逻辑删除。
> - `shop`：审核流转用 `status` 字段，驳回后**更新同一行**重新提交，故唯一键 `user_id` 不冲突。

## 3. ER 关系

```
                    ┌─────────────┐
                    │  sys_user   │
                    └──────┬──────┘
               1:1        │        1:n (favorite/message)
                    ┌──────▼──────┐
                    │    shop     │
                    └──────┬──────┘
     1:n ┌────────┬────────┼────────┬────────┐
   ┌─────▼────┐┌──▼──────┐┌▼───────┐┌▼─────┐┌▼───────┐
   │ product  ││shop_link││sales/  ││click ││message │
   └─────┬────┘│         ││prod/   ││_log  │└───┬────┘
         │n:1  │         ││cost_   │└──────┘    │n:1
   ┌─────▼─────┐│         ││record  │           │sys_user
   │ category  ││         │└─┬──┬──┘
   │ (小类)    ││         │  │  └──n:1── cost_type
   └─────┬─────┘│         │  └─────n:1── channel
         │n:1  │
   ┌─────▼─────┐│
   │ category  ││
   │ (大类)    ││
   └───────────┘│
```

**关系说明**

| 关系 | 说明 |
| --- | --- |
| `sys_user` 1:1 `shop` | 一个用户最多一个店铺（管理员/普通用户无店铺） |
| `shop` 1:n `product` | 店铺下多个展示产品 |
| `shop` 1:n `shop_link` | 店铺可配多个拼多多链接（店铺级/产品级） |
| `category` 自关联 | 大类(parent_id=0) 1:n 小类 |
| `category`(小类) 1:n `product` | 产品归属某个品种（小类） |
| `category`(小类) 1:n `sales/production/cost_record` | **产销成本按"品种(小类)"统计** |
| `channel` 1:n `sales_record` | 销售记录关联渠道 |
| `cost_type` 1:n `cost_record` | 成本记录关联成本类型 |
| `sys_user` n:m (经 favorite) | 收藏/关注产品或店铺 |
| `sys_user` 1:n `message`，`shop` 1:n `message` | 用户留言给店铺 |

> **关键建模决策**：产销/成本记录**直接关联 `category`（小类/品种）**，而不是 `product`。因为经营数据是按"某年某品种"记录的（如"2023 红富士 电商渠道 卖了 5000 斤"），品种才是统计维度；`product` 仅是面向访客的图文展示条目。两者通过 `category_id` 打通。

## 4. 建表 DDL

### 4.1 用户表 sys_user

```sql
CREATE TABLE sys_user (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  username        VARCHAR(32)   DEFAULT NULL COMMENT '登录账号(可空)',
  phone           VARCHAR(20)   DEFAULT NULL COMMENT '手机号',
  password        VARCHAR(100)  DEFAULT NULL COMMENT '密码(BCrypt加密)',
  role            TINYINT       NOT NULL DEFAULT 1 COMMENT '角色:1-普通用户,2-商家,3-管理员',
  nickname        VARCHAR(50)   DEFAULT NULL COMMENT '昵称',
  avatar          VARCHAR(255)  DEFAULT NULL COMMENT '头像URL',
  status          TINYINT       NOT NULL DEFAULT 1 COMMENT '状态:1-正常,0-禁用',
  last_login_time DATETIME      DEFAULT NULL COMMENT '最后登录时间',
  create_time     DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time     DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  deleted         TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除:0-否,1-是',
  PRIMARY KEY (id),
  UNIQUE KEY uk_username ((CASE WHEN deleted = 0 THEN username ELSE NULL END)),
  UNIQUE KEY uk_phone ((CASE WHEN deleted = 0 THEN phone ELSE NULL END))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

### 4.2 店铺表 shop

```sql
CREATE TABLE shop (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '店铺ID',
  user_id       BIGINT UNSIGNED NOT NULL COMMENT '所属用户ID',

  region        VARCHAR(100) DEFAULT NULL COMMENT '所在地区(省市区县乡镇)',
  address       VARCHAR(255) DEFAULT NULL COMMENT '详细地址',

  wechat        VARCHAR(50)  DEFAULT NULL COMMENT '微信号',
  description   TEXT         COMMENT '店铺简介',
  license_image VARCHAR(255) DEFAULT NULL COMMENT '资质证明图片URL(可选)',
  status        TINYINT      NOT NULL DEFAULT 0 COMMENT '审核状态:0-待审核,1-通过,2-驳回',
  reject_reason VARCHAR(255) DEFAULT NULL COMMENT '驳回原因',
  create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

### 4.4 产品表 product

```sql
CREATE TABLE product (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '产品ID',
  shop_id      BIGINT UNSIGNED NOT NULL COMMENT '所属店铺ID',
  category_id  BIGINT UNSIGNED NOT NULL COMMENT '品种(小类)ID',
  name         VARCHAR(100) NOT NULL COMMENT '产品名称(展示用,如"红富士苹果5斤装")',
  unit         VARCHAR(20)  DEFAULT NULL COMMENT '计量单位(斤/公斤/箱/吨)',
  images       JSON         COMMENT '图片URL列表',
  description  TEXT         COMMENT '产品介绍',
  origin       VARCHAR(100) DEFAULT NULL COMMENT '产地',
  season       VARCHAR(50)  DEFAULT NULL COMMENT '上市季节',
  status       TINYINT      NOT NULL DEFAULT 0 COMMENT '状态:0-草稿,1-已上架,2-已下架',
  is_recommend TINYINT      NOT NULL DEFAULT 0 COMMENT '是否推荐:0-否,1-是',
  price        DECIMAL(14,2) DEFAULT NULL COMMENT '价格(商城预留)',
  stock        INT           DEFAULT NULL COMMENT '库存(商城预留)',
  sku          VARCHAR(100)  DEFAULT NULL COMMENT '规格/SKU(商城预留)',
  create_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  deleted      TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除:0-否,1-是',
  PRIMARY KEY (id),
  KEY idx_shop_cat (shop_id, category_id),
  KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='产品表';
```

## 6. 核心报表 SQL 示例

> 均以单商家 `shop_id = :shopId` 为例，管理员可去掉该条件汇总全平台。以下查询可作为接口实现，或按需封装成视图。

### 6.1 利润核算（按年份）

```sql
SELECT
  t.year,
  t.sales_amount,
  COALESCE(c.cost_amount, 0) AS cost_amount,
  t.sales_amount - COALESCE(c.cost_amount, 0) AS profit,
  CASE WHEN t.sales_amount = 0 THEN NULL
       ELSE ROUND((t.sales_amount - COALESCE(c.cost_amount, 0)) / t.sales_amount * 100, 2)
  END AS profit_rate
FROM (
  SELECT year, SUM(amount) AS sales_amount
  FROM sales_record
  WHERE shop_id = :shopId AND deleted = 0
  GROUP BY year
) t
LEFT JOIN (
  SELECT year, SUM(amount) AS cost_amount
  FROM cost_record
  WHERE shop_id = :shopId AND deleted = 0
  GROUP BY year
) c ON c.year = t.year
ORDER BY t.year;
```

### 6.2 单品跨年趋势（产量/销量/销售额，双 Y 轴折线）

```sql
SELECT
  y.year,
  COALESCE(p.production, 0) AS production,
  COALESCE(s.sales_qty, 0)  AS sales_qty,
  COALESCE(s.sales_amount, 0) AS sales_amount
FROM (
  SELECT DISTINCT year FROM (
    SELECT year FROM sales_record   WHERE shop_id = :shopId AND category_id = :catId AND deleted = 0
    UNION
    SELECT year FROM production_record WHERE shop_id = :shopId AND category_id = :catId AND deleted = 0
  ) yy
) y
LEFT JOIN (
  SELECT year, SUM(quantity) AS production
  FROM production_record
  WHERE shop_id = :shopId AND category_id = :catId AND deleted = 0
  GROUP BY year
) p ON p.year = y.year
LEFT JOIN (
  SELECT year, SUM(quantity) AS sales_qty, SUM(amount) AS sales_amount
  FROM sales_record
  WHERE shop_id = :shopId AND category_id = :catId AND deleted = 0
  GROUP BY year
) s ON s.year = y.year
ORDER BY y.year;
```

### 6.3 某年各产品销售额对比（柱状图，按品种/小类）

```sql
SELECT
  c.id   AS category_id,
  c.name AS category_name,
  SUM(s.amount) AS amount
FROM sales_record s
JOIN category c ON c.id = s.category_id
WHERE s.shop_id = :shopId AND s.year = :year AND s.deleted = 0
GROUP BY c.id, c.name
ORDER BY amount DESC;
```

### 6.4 某年渠道占比（饼图）

```sql
SELECT
  ch.name AS channel_name,
  SUM(s.amount) AS amount
FROM sales_record s
JOIN channel ch ON ch.id = s.channel_id
WHERE s.shop_id = :shopId AND s.year = :year AND s.deleted = 0
GROUP BY ch.id, ch.name
ORDER BY amount DESC;
```

### 6.5 某年大类占比（饼图，大类由 parent 推导）

```sql
SELECT
  p.id   AS big_category_id,
  p.name AS big_category_name,
  SUM(s.amount) AS amount
FROM sales_record s
JOIN category c ON c.id = s.category_id
JOIN category p ON p.id = c.parent_id
WHERE s.shop_id = :shopId AND s.year = :year AND s.deleted = 0
GROUP BY p.id, p.name
ORDER BY amount DESC;
```

### 6.6 销售额 Top N（排行）

```sql
SELECT
  c.name AS category_name,
  SUM(s.amount) AS amount
FROM sales_record s
JOIN category c ON c.id = s.category_id
WHERE s.shop_id = :shopId AND s.deleted = 0
GROUP BY c.id, c.name
ORDER BY amount DESC
LIMIT :topN;
```

## 7. 索引设计说明

| 表 | 索引 | 支撑查询 |
| --- | --- | --- |
| `sales_record` | `(shop_id, category_id, year)` | 单品跨年趋势 |
| `sales_record` | `(shop_id, channel_id, year)` | 渠道占比 |
| `sales_record` | `(shop_id, year)` | 年度汇总/利润 |
| `production_record` / `cost_record` | `(shop_id, category_id, year)` | 产量/成本按品种聚合 |
| `product` | `(shop_id, category_id)`、`(status)` | 商家产品列表、上架筛选 |
| `shop_link` | `(shop_id)`、`(product_id)` | 引流链接查询 |
| `click_log` | `(shop_id, click_time)` | 跳转统计按时间聚合 |

> 数据量小（单商户几年数据，通常 < 10 万行），上述索引足够；无需分库分表。报表若访问频繁，可在服务层加 Redis 缓存（如缓存当日/当年的聚合结果）。

## 9. 待确认项对设计的影响

| 待确认项 | 当前设计 | 若变更的调整 |
| --- | --- | --- |
| 计量单位换算 | `unit` 存字符串，**不做自动换算** | 若需换算：加"基准单位 + 换算系数"（如统一折算为斤），或录入时强制统一单位 |
| 成本记录粒度 | 支持**分项**（`cost_type_id`）+ **简化**（`cost_type` 选"总成本(简化)"一条） | 已兼容两种 |
| 品种粒度 | 大类 + 小类两级 | 如需第三级，`category` 自关联天然支持，改 `level` 判断即可 |
| 拼多多链接形式 | 存 `link_url` 字符串 | 若拼多多要求短链/口令，`link_url` 字段足够，展示层适配 |
